# Проверка расчётов бота (ноябрь 2026)

Проверены: `serverless/tgcloud/lib/balance.js` (движок), `fields.js` (хранение поля, обновление по дням, полив, проверка влажности), `weather.js`, `planner.js` (ввод в чате), `demo.js`, `i18n.js` (показ объёмов).

## 1. Формулы — верны

Тест `serverless/test/independent-audit.test.js` заново выводит каждую величину прямо из определений FAO-56 (не используя код бота) и сравнивает с ботом на **5000 случайных полях** (все культуры, почвы, способы полива, гектары и сотки, стрессовые и нестрессовые состояния, дожди):

| Величина | Формула | Совпадает |
|---|---|---|
| TAW | 1000 · (θFC − θWP) · Zr (FAO-56, ур. 82) | да |
| RAW | p · TAW (ур. 83) | да |
| Kc | постоянный в начале, линейный в развитии и созревании (ур. 66) | да |
| Ks | (TAW − Dr) / ((1 − p) · TAW), если Dr > RAW (ур. 84) | да |
| ETc | Ks · Kc · ET₀ | да |
| Дефицит | Dr = clamp(Dr вчера + ETc − Peff, 0, TAW) | да |
| Решение | критично, если Dr > RAW; поливать, если Dr ≥ min(порог техники, RAW) | да |
| Объём | нетто = Dr · 10 · S (1 мм на 1 га = 10 м³); брутто = нетто / КПД | да |
| Насос | часы = V / Q; ₸ = часы · кВт · тариф | да |
| Сотки | 1 сотка = 0,01 га | да |
| Показ объёма | меньше 1 м³ показывается в литрах | да |
| Отметка полива | Dr −= V · КПД / (10 · S) | да |

Расхождений нет (допуск 10⁻⁹).

## 2. Найденные проблемы

### 2.1 После пропуска дней бот недосчитывает расход воды — **важно, исправлено**
Если поле не открывали несколько дней, при следующем открытии добавляется испарение **только за сегодня**. Проверка: поле томатов, ETc ≈ 5,6 мм/сут, открыто через 4 дня — дефицит вырос на 5,6 мм вместо ≈ 22 мм. Бот показывает предупреждение «Пропуск наблюдений», но объём полива всё равно занижен. Фермер, который открывает бота раз в неделю, будет поливать заметно меньше нужного.

### 2.2 Прогноз на сегодня записывается как уже случившееся — **важно, исправлено**
Первое открытие за день закрепляет прогноз испарения и дождя как факт и больше не исправляется. Если обещанный дождь (≥ 5 мм) не пошёл, дефицит остаётся заниженным, и бот может сказать «можно не поливать». Эта задача уже описана в `COMPETITION_ROADMAP.md` (P0.1), но в рабочем боте не исправлена. В анализе чувствительности проверен только обратный случай («дождь не учли»), он безвреден; случай «обещанный дождь не пошёл» ещё не проверялся.

**Исправление 2.1 и 2.2 (предложение):** брать у Open-Meteo вместе с сегодняшним прогнозом прошедшие дни (`past_days`), закрывать каждый завершённый день по его фактическим (модельным) данным по порядку, а прогноз на сегодня использовать только для совета, не записывая его в состояние поля.

### 2.3 Повторная отправка поля с другими данными молча игнорируется — **средне, исправлено**
Поле узнаётся по координатам, площади и культуре. Если фермер исправил почву, способ полива или состояние почвы и отправил поле снова, бот вернёт старое поле со старыми параметрами и ничего не скажет. Проверка: суглинок/капля → отправили песок/арык → в поле осталось суглинок/капля.

**Исправление (предложение):** если изменились почва, способ полива, культура-параметры или дата посева — пересчитать поле с новыми данными (или спросить «обновить поле?»), а не возвращать старое молча.

## 2.4 Как исправлено (`fields.js`, `weather.js`)

- Погода запрашивается вместе с 30 прошедшими днями (`past_days=30`). Значения прошедших дней — модельный анализ провайдера, а не датчик на поле.
- Поле хранит **закрытое состояние** на конец последнего завершённого дня (`closed_day`, `closed_deficit`). При открытии каждый пропущенный день закрывается по порядку по своей погоде; день без данных считается разрывом (`gap_days`) и показывается предупреждением.
- Прогноз на сегодня даёт только совет. При обновлении прогноза совет пересчитывается от закрытого состояния и не накапливается повторно. Обещанный, но не выпавший дождь при закрытии дня заменяется фактическим.
- Поливы и проверки влажности записываются с днём и проигрываются при закрытии этого дня (полив вычитает нетто-слой, проверка задаёт уровень).
- Старые поля переводятся автоматически: прошедший `last_day` принимается как закрытый, а если это сегодня, состояние на начало дня восстанавливается из сохранённого расчёта.
- Повторная отправка поля: изменились почва, способ полива, условия, параметры культуры → баланс начинается заново (старые поливы в новый расчёт не попадают); изменился только насос → обновляется стоимость, запас влаги сохраняется; ничего не изменилось → бот сообщает, что поле уже есть, и подсказывает кнопку проверки влажности. Число дней из формы при повторной отправке не сбрасывает поле: дату посева бот ведёт сам.
- Тесты: `serverless/test/day-logic.test.js` (9 сценариев: пропуск 4 дней, несбывшийся дождь, обновление прогноза, полив и проверка при закрытии дня, разрыв данных, миграция старых полей, повторная отправка, устаревший черновик). Все тесты: 729 из 730, падает только прежний `transport.test.js`, которому нужна папка `frontend`.
- Старый Python-бот не менялся (выведен из эксплуатации).

## 3. Упрощения модели (не ошибки, но назвать в работе)

| Что | Как в боте | Как в FAO-56 | Влияние |
|---|---|---|---|
| Доля p | постоянная из таблицы | поправка p = p_табл + 0,04·(5 − ETc) | в жару (ETc 8 мм) RAW завышен примерно на 0,12·TAW, порог стресса наступает раньше, чем думает бот |
| Эффективные осадки | 0 при < 5 мм, иначе 0,75·P | метод не задан | правило проекта |
| Глина | θFC 0,45 / θWP 0,30 | в типичных таблицах для глины влагоёмкость ниже (сверить с таблицей 19 FAO-56) | запас воды (0,15) такой же, как у суглинка, — модель их не различает |
| Рис | Kc = 1,25 всегда, КПД 0,50 при любом способе полива | Kc риса зависит от стадии | грубая оценка |
| Теплица | ET₀ · 0,70, если не введён измеренный | — | допущение проекта, в отчёте подписано |
| Экономика «против арыка» | считается внутри результата | — | в рабочем боте **не показывается**; показывается только стоимость рекомендуемого полива |
