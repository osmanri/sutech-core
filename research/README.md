# Исследование: Su-Tech против полива по графику

Компьютерное исследование на **реальной погоде** 5 орошаемых регионов Казахстана за 5 сезонов (2021–2025). Это **модель против модели**, а не полевое измерение: результаты показывают потенциал и слабые места, а проверять их нужно опытом (`experiment/`) и полем.

## Что сравнивается

- **Su-Tech:** каждый день решение принимает рабочий движок бота (`bot/water_balance.py`, версия `fao56.6`) со своей собственной оценкой дефицита.
- **График:** фиксированная норма каждые N дней. Норма считается по средней многолетней потребности культуры **в том же месте**, то есть это разумный фермер, а не «соломенное чучело».
- **Безопасный график:** та же схема, но норма увеличена до минимального множителя, при котором **каждый** сезон даёт не меньше 98% урожая. Это сравнение при одинаковом результате.
- **Оборудование у обеих стратегий одно и то же** (капля против капли, арык против арыка), поэтому разница возникает только из-за того, когда и сколько поливать.

**Модель:** баланс корнеобитаемого слоя по FAO-56, глава 8, с коэффициентом стресса Ks (уравнение 84). Глубинный сток считается, сходимость водного баланса не хуже 3·10⁻¹² мм.

**Урожай:** оценка по FAO-33, `1 − Ya/Ym = Ky·(1 − ETa/ETm)`, где Ky = 0,85 для хлопка и 1,25 для кукурузы.

**Погода:** NASA POWER (температура, точка росы, ветер, радиация, осадки). ET₀ считается проектным модулем Пенмана–Монтейта `bot/et0.py`, сверенным с примером 18 FAO-56. Для проверки: за три дня мая 2024 года в Туркестане ET₀ по NASA + `et0.py` = 4,9 / 5,5 / 5,9 мм, по Open-Meteo = 5,3 / 5,3 / 5,6 мм.

## Главные результаты (суглинок, 25 сезонов на каждую строку)

|---|---|---|---|---|
| Хлопок, капля | 11 321 | 15 536 | **27%** | 25 из 25 |
| Хлопок, арык | 19 751 | 30 199 | **34%** | 25 из 25 |
| Кукуруза, капля | 9 039 | 11 009 | **18%** | 25 из 25 |
| Кукуруза, арык | 15 781 | 21 848 | **27%** | 25 из 25 |

Полная таблица: `results/simulation_summary.md`.

**Важно для защиты:** против **обычного** графика с той же средней нормой Su-Tech тратит на 2–9% **больше** воды. Зато у Su-Tech 0 дней стресса против 38–65 у графика, и урожай 100% против 84–90%. Экономия появляется только при сравнении **при одинаковом урожае**, и так её и нужно формулировать.

Почему график проигрывает: он поливает после дождя и сверх ёмкости почвы. Чтобы пережить жаркие периоды, безопасному графику приходится лить с запасом в 1,25–1,65 раза, и 230–520 мм воды за сезон уходят в глубину. У Su-Tech эти потери составляют 2–24 мм.

## Чувствительность (хлопок; `results/sensitivity_*.md`)

| Что пошло не так | Последствия |
|---|---|
| Случайная ошибка прогноза ET₀ ±10–30% | Почти без последствий: стресса нет, экономия 23–34% |
| Дожди не учтены вообще | Почти без последствий |
| Фермер указал не ту почву | Без последствий (порог технологии полива ниже RAW любой почвы) |
| **Прогноз всегда занижает ET₀ на 20%** | **71–73 дня стресса, урожай 94–96% (в худший год 91%)** |
| То же + **проверка влажности почвы раз в 7 дней** | Стресса нет, экономия 21–30% |
| То же + проверка раз в 3 дня | Стресса нет, но экономия меньше: шум датчика вызывает лишние поливы |
| То же + **трёхуровневая проверка в боте** («влажная / нормальная / сухая») раз в 7 дней | **Стресса нет, экономия 19% (капля) и 21% (арык)** — именно эта кнопка есть в боте |
| То же + трёхуровневая проверка раз в 3 дня | Стресса нет, экономия 15% (капля) и 9% (арык): частые грубые проверки вызывают лишние поливы |

**Вывод:** модель устойчива к случайным ошибкам, но не к систематическим. Ошибка накапливается, потому что модель не видит реальной почвы. Дешёвая проверка влажности раз в неделю это исправляет, поэтому в боте добавлена кнопка «Проверил влажность почвы» (`soil:` в `serverless/tgcloud/lib/bot.js`). Рекомендация пользователю: проверять **раз в неделю**. Опыт с горшками проверяет именно это.

## Ограничения (обязательно назвать в работе)

- Модель против модели. Это не измерение урожая и воды на поле.
- Погода — данные реанализа для координат областных центров, а не метеостанции хозяйств.
- Одна почва в основном расчёте, фиксированная дата посева (1 мая), без засоления и без капиллярного подъёма.
- В основном расчёте Su-Tech знает погоду точно. Ошибки прогноза разобраны только в анализе чувствительности.
- Урожай оценён по формуле FAO-33, а не измерен.
- Капельный режим Su-Tech поливает почти каждый день (94–129 раз за сезон), на практике это требует автоматики.

## Как повторить

```bash
python -m research.simulate      # основная таблица  -> research/results/simulation_*
python -m research.sensitivity   # чувствительность  -> research/results/sensitivity_*
python -m unittest test_research_simulation
```

Погода хранится в `research/data/weather/`, поэтому расчёт повторяется без интернета. Если удалить файлы, они скачаются заново.
