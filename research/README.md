# Исследование: Su-Tech против полива по графику

Компьютерное исследование на **реальной погоде** 5 орошаемых регионов Казахстана за 5 сезонов (2021–2025). Это **модель против модели**, а не полевое измерение: результаты показывают потенциал и слабые места, а проверять их нужно опытом (`experiment/`) и полем.

## Что сравнивается

- **Su-Tech:** ежедневное решение принимает Python-движок (`bot/water_balance.py`) с накопленной оценкой дефицита. Для опубликованной серии используется конфигурация периода `fao56.6`.
- **Обычный график:** фиксированная норма каждые N дней, рассчитанная по средней многолетней потребности культуры **в том же месте**.
- **Лучший график (главное сравнение):** перебираются интервал (капля 1–7 дней, арык 5–21 день) и норма. Выбирается вариант с наименьшим расходом воды, при котором **каждый** из пяти сезонов даёт не меньше 98% урожая. Подбор идёт с знанием всех пяти сезонов наперёд, чего у фермера не бывает, поэтому это **самый сильный соперник**. Su-Tech с ним сравнивается при одинаковом урожае.
- **Оборудование у обеих стратегий одно и то же** (капля против капли, арык против арыка), поэтому разница возникает только из-за того, когда и сколько поливать.

**Модель:** баланс корнеобитаемого слоя по FAO-56, глава 8, с коэффициентом стресса Ks (уравнение 84). Глубинный сток считается, сходимость водного баланса не хуже 10⁻¹¹ мм на всех прогонах.

**Урожай:** оценка по FAO-33, `1 − Ya/Ym = Ky·(1 − ETa/ETm)`, где Ky = 0,85 для хлопка и 1,25 для кукурузы.

**Погода:** NASA POWER (температура, точка росы, ветер, радиация, осадки). ET₀ считается проектным модулем Пенмана–Монтейта `bot/et0.py`, сверенным с примером 18 FAO-56. Для проверки: за три дня мая 2024 года в Туркестане ET₀ по NASA + `et0.py` = 4,9 / 5,5 / 5,9 мм, по Open-Meteo = 5,3 / 5,3 / 5,6 мм.

## Главные результаты (суглинок, посев 1 мая, 25 сезонов на строку)

| Культура, полив | Su-Tech, м³/га | Лучший график, м³/га | Su-Tech экономит (95% интервал) | Лучший / худший из 25 сезонов | Сезонов, где Su-Tech тратит меньше |
|---|---|---|---|---|---|
| Хлопок, капля | 11 321 | 15 117 | **25%** (23–27%) | 34% / 18% | 25 из 25 |
| Хлопок, арык | 19 751 | 27 600 | **28%** (26–30%) | 38% / 20% | 25 из 25 |
| Кукуруза, капля | 9 039 | 10 709 | **15%** (14–17%) | 25% / 9% | 25 из 25 |
| Кукуруза, арык | 15 781 | 19 525 | **19%** (17–21%) | 30% / 12% | 25 из 25 |

Полная таблица: `results/simulation_summary.md`.

**Исторические интервалы** получены бутстрэпом (10 000 повторов, фиксированное зерно) с перевыборкой отдельных случаев «место × год». Такой расчёт предполагает независимость. Соседние регионы в один год имеют похожую погоду, а пять сезонов в одном регионе разделяют местные условия. По каждой строке таблицы экономия наблюдалась во всех проверенных сезонах. В худшем сезоне каждой строки она составляла 9–20%.

**Лучший график** оказался ежедневным для капли и раз в 5 дней для арыка, с нормой в 1,18–1,49 раза выше средней потребности. Даже он даёт 6–10 дней лёгкого стресса за сезон (урожай 99,2–99,4%) и теряет 210–394 мм воды в глубину. У Su-Tech стресса нет, а потери 2–24 мм.

**Важно для защиты:** против **обычного** графика с той же средней нормой Su-Tech тратит на 2–9% **больше** воды, зато у Su-Tech 0 дней стресса против 38–65 у графика, и урожай 100% против 84–90%. Поэтому экономию нужно формулировать **только при равном урожае**.

**Как менялась главная цифра.** В первой версии сравнение шло с графиком фиксированного интервала (5 дней для капли, 10 для арыка), и экономия выходила 18–34%. На песке такой график вообще не может дать 98% урожая. Поэтому соперник заменён на лучший возможный график, и цифра стала 15–28%. Она меньше, но честнее.

## Другие почвы и даты посева (`results/robustness.md`)

Проверено 36 комбинаций: 3 почвы × 3 даты посева (15 апреля, 1 мая, 15 мая) × 2 культуры × 2 способа полива, в каждой 25 сезонов.

| Почва | Экономия против лучшего графика | Худший сезон |
|---|---|---|
| Песок | 26–42% | 20% |
| Суглинок | 14–29% | 6% |
| Глина | как суглинок (см. ниже) | 6% |

- Su-Tech потратил меньше воды **в каждом сезоне во всех 36 комбинациях**, стресса у Su-Tech не было ни разу.
- **Глина совпала с суглинком** не случайно: в параметрах проекта у них одинаковый запас доступной воды (θFC − θWP = 0,15). Модель их не различает, поэтому по сути проверено **две** разные почвы. Это ограничение параметров, а не результат.

## Чувствительность (хлопок; `results/sensitivity_*.md`)

Сравнение идёт с тем же лучшим графиком.

| Что пошло не так | Последствия |
|---|---|
| Случайная ошибка прогноза ET₀ ±10–30% | Почти без последствий: стресса нет, экономия 21–28% |
| Дожди не учтены вообще | Почти без последствий |
| Фермер указал не ту почву | Без последствий (порог технологии полива ниже RAW любой почвы) |
| **Прогноз всегда занижает ET₀ на 20%** | **71–73 дня стресса, урожай 94–96% (в худший год 91%)** |
| То же + **трёхуровневая проверка в боте** («влажная / нормальная / сухая») раз в 7 дней | **Стресса нет, экономия 14–17%** — именно эта кнопка есть в боте |
| То же + трёхуровневая проверка раз в 3 дня | Стресса нет, но экономия почти пропадает (0–12%): частые грубые проверки вызывают лишние поливы |
| То же + точный датчик влажности (ошибка ±10 мм) раз в 7 дней | Стресса нет, экономия 19–23% |

**Вывод:** в этой серии правильная еженедельная категория влажности убрала стресс при систематической ошибке ET₀. Категория рассчитывалась из известного модели дефицита, полив выполнялся в день рекомендации. В боте есть кнопка «Проверил влажность почвы» (`soil:` в `serverless/tgcloud/lib/bot.js`). [Отдельная проверка устойчивости](OBSERVATION_ROBUSTNESS.md) показывает ситуации, в которых ошибочные категории, пропуски и задержки полива ухудшают расчётный урожай или устраняют экономию воды. Частоту проверок предстоит проверить в опыте.

## Когда модель ошибается насчёт самого поля (`results/misspecified.md`)

В основной симуляции бот и «настоящее поле» считаются одними уравнениями, и это льстит боту. Поэтому добавлена проверка, где **настоящее поле отличается от параметров бота**: Kc культуры ±15%, запас доступной воды почвы ±20%, и два худших сочетания. Бот решает по своим (неверным) параметрам, а лучший график подбирается **на настоящем поле** со знанием всех сезонов, то есть против самого сильного соперника. Su-Tech запускается без поправок и с еженедельной проверкой «влажная / нормальная / сухая». Хлопок и кукуруза, капля и арык, 5 регионов × 5 сезонов (100 сезонов в строке).

| Настоящее поле отличается так | Su-Tech с проверкой раз в неделю: воды относительно лучшего графика (среднее / худший сезон) | Дней стресса (Su-Tech / график) | Урожай Su-Tech (худший сезон) |
|---|---|---|---|
| Модель верна | −17,5% / +1,0% | 0,0 / 8,2 | 1,000 |
| Культура тратит на 15% меньше | −4,0% / +13,3% | 0,0 / 9,4 | 1,000 |
| Культура тратит на 15% больше | −17,2% / −2,8% | 0,1 / 7,5 | 1,000 |
| Почва держит на 20% меньше | −22,6% / −9,2% | 0,2 / 7,1 | 0,999 |
| Почва держит на 20% больше | −12,3% / +10,1% | 0,0 / 9,6 | 1,000 |
| Худший для урожая случай: культура +15%, почва −20% | −22,8% / −11,7% | 0,4 / 6,9 | 0,997 |
| Худший для воды случай: культура −15%, почва +20% | **+2,8%** / +27,7% | 0,0 / 10,6 | 1,000 |

**Выводы, которые нужно говорить честно:**
- **Без еженедельной проверки** бот, который недооценивает потребность культуры на 15%, даёт 28 дней стресса за сезон (в худшем сочетании 45), урожай в худшем сезоне 0,92. В этой серии правильная проверка раз в неделю снижает стресс почти до нуля (0,1–0,4 дня).
- **Экономия зависит от того, насколько бот прав:** от около 23% (почва держит на 20% меньше, то есть бот осторожнее) до **нуля и ниже**: когда бот переоценивает потребность культуры на 15% и почва держит на 20% больше, он тратит в среднем на 2,8% **больше** воды, чем лучший график, а в худшем сезоне на 28% больше, при полном урожае.
- При правильной еженедельной проверке в приведённых вариантах стресс и потери урожая малы. Если модель завышает потребность культуры, возрастает расход воды.
- Цифры «15–28%» из основной таблицы остаются верхней оценкой для случая, когда параметры бота близки к настоящим. Даже тогда по этой таблице среднее −17,5% (а не 15–28%, потому что здесь усреднены обе культуры и оба способа полива). Для агрономов нужно называть и диапазон «от 23% до примерно нуля».

**Версия движка в исследовании.** Основная таблица и эта проверка посчитаны **без** поправки Kc на смоченную часть поверхности при капельном поливе (FAO-56, ур. 60), потому что опубликованные цифры получены до неё. Чтобы воспроизвести их, ничего делать не нужно: исследование по умолчанию выключает поправку. С поправкой: `SUTECH_STUDY_WETTED_FRACTION=on python -m research.simulate` (экономия на капле растёт: хлопок 25% → 31%, кукуруза 15% → 20%).

Запуск: `python -m research.misspecified` (около 20 секунд, погода берётся из кэша).

## Ограничения (обязательно назвать в работе)

- Модель против модели. Это не измерение урожая и воды на поле.
- Погода — данные реанализа для координат областных центров, а не метеостанции хозяйств.
- Почвы в модели различаются только запасом доступной воды; глина и суглинок совпадают. Нет засоления и капиллярного подъёма.
- В основном расчёте бот и «настоящее поле» считаются одними уравнениями (модель против модели); частично закрыто проверкой `misspecified.md`, где параметры настоящего поля другие. Это всё равно симуляция, а не поле.
- В основном расчёте Su-Tech знает погоду точно. Ошибки прогноза разобраны только в анализе чувствительности.
- Лучший график подобран с знанием всех сезонов наперёд: это выгодно графику, но реальный фермер так не может.
- Урожай оценён по формуле FAO-33, а не измерен.
- Капельный режим Su-Tech поливает почти каждый день (94–129 раз за сезон), на практике это требует автоматики. Лучший график для капли тоже ежедневный.

## Как повторить

```bash
python -m research.simulate      # основная таблица        -> research/results/simulation_*
python -m research.sensitivity   # чувствительность        -> research/results/sensitivity_*
python -m research.robustness    # почвы и даты посева      -> research/results/robustness.* (~4 мин)
python -m research.observation_robustness  # ошибки наблюдения и задержки -> research/results/observation_robustness_*.md
python -m research.plots         # рисунки                  -> docs/img/*.svg
python -m unittest test_research_simulation
```

Погода хранится в `research/data/weather/`, поэтому расчёт повторяется без интернета. Если удалить файлы, они скачаются заново.
